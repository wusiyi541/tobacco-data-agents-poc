# ⑤ 元数据补充

**定位**：元数据智能预填。按元数据规范，库表技术元数据由系统自动采集，但**业务元数据**（业务描述、业务口径、更新频率、来源系统）依赖人工填报——本智能体把填报从"逐条手写"变成"AI 预填 + 人工确认"。

![效果](../docs/05-元数据补充-AI一键填充.png)

## 组成

| 文件 | 说明 |
|---|---|
| `build_poc_data.py` | 生成虚构演示数据：`catalog_5.json`（5 条目录）+ `meta_poc.db`（5 张模拟库表，每表 80~100 行随机数据） |
| `poc_server.py`（8092） | 本地服务：**① 探查**（行数/空值率/唯一值/类型推断/样例值）→ **② AI 填充**（调 Dify Workflow 生成建议）→ **③ 采纳**（人工确认后出填报单） |
| `index.html` | 发起变更页：选目录 → 业务元数据表单 → AI 一键填充 → 逐字段确认 |
| `build_meta_workflow.py` | 自动构建 Dify Workflow |

## 设计要点

- **AI 填充走只读探查**：模型拿到的是服务端探查摘要（字段名、空值率、样例值，limit 100），不下探生产数据、不写库
- **建议带置信度与依据**：每个字段建议输出 `{value, confidence, basis}`，低置信度项必须人工确认
- **落库走 API + 人工确认**：确认后的结果生成填报单走「提交审批」，由元数据管理流程落库（AI 不直接写）

## 运行

```bash
python build_poc_data.py           # 生成 catalog_5.json + meta_poc.db（虚构数据）
python poc_server.py --port 8092   # http://127.0.0.1:8092
```
