# ④ 数据模型符合性检查

**定位**：把《元数据管理规范》的建表审核条款转成可执行规则，对建表语句（DDL）或表结构清单**逐条自动判定**，输出不符合项 + 引用条款 + 建议改法。对话为首选交互（对话框内上传 DDL），页面嵌入为备选。

![效果](../docs/04-数据模型符合性检查-对话式检查.png)

## 组成

| 文件 | 说明 |
|---|---|
| `rules_engine.py` | 服务端规则引擎：**22 条确定性规则**（命名/注释/主键/类型/字段语义等维度），输入 DDL 输出结构化判定证据 |
| `poc_server.py`（8093） | 本地服务：接收 DDL → 规则引擎 → 组装证据 → 调 Dify Workflow 生成结构化建议 |
| `build_workflow.py` | 自动构建 Dify Workflow（规则证据作为确定性输入，模型只做归并与表达） |
| `index.html` / `demo.html` | 两种形态演示页：页面嵌入 / 对话式 |
| `samples/` | 9 份 DDL / 表结构样例（含典型违规样例） |
| `export_rules.py` | 规则清单导出（条款 → 判据 → 提示语） |
| `test_flow.py` | 端到端用例 |

## 设计要点

- **数由代码算，话由模型说**：符合性判定全部由规则引擎完成（确定性），模型依据判定证据生成建议（`建议改法` 附条款依据），不参与判定本身
- **证据可追溯**：每条不符合项都带「引用条款 + 涉及字段 + 建议改法」，页面可逐条确认/忽略
- **知识来源**：条款来自《元数据管理规范》的三级元模型与规范性审核要求（仓库内为示例稿表述）

## 运行

```bash
python poc_server.py --port 8093   # http://127.0.0.1:8093
python rules_engine.py samples/xxx.sql   # 单独跑规则引擎
```
